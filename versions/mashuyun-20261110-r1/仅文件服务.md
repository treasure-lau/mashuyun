# 仅文件服务

已有安装包时，可以只部署文件节点，完成上传、版本管理、发布和下载。此路径不需要构建机、构建 SDK、构建任务或虚拟构建产物。

## 安装文件节点

1. 准备[受支持的机器、Docker、存储与 HTTPS]({{ '/versions/mashuyun-20261110-r1/requirements/' | relative_url }})。Apple 芯片 Mac 的文件服务及数据库在容器中运行。
2. 在平台“客户节点 → 开始接入”选择“仅文件服务”和实际机器平台，下载本组织配置、节点包和独立验包工具，完成[可信核验]({{ '/versions/mashuyun-20261110-r1/downloads/' | relative_url }})。
3. 在接入助手选择“仅文件服务”，选择全新安装目录，填写下载入口与证书或同机网关配置，检查环境。
4. 使用本组织的文件节点登记码登记，完成首次授权确认，等待自动授权、安装、启动和服务检查。原节点已登记时沿原向导继续。

文件节点首次完成合格就绪核验，也会启动组织唯一的 30 天试用。今后接入构建机或重装节点不会延长这段期限。

## 上传并发布安装包

在平台创建或选择真实项目及测试环境。仅使用文件服务时，仓库地址可以留空，无需填写虚构地址；文件流程不会拉取源码或要求构建机。以后启用构建时，再补齐真实仓库、分支及对应构建配置。

打开项目，通过客户文件节点提供的授权页面上传实际 APK 或 IPA，等待元数据解析完成，选择该版本并确认发布。文件字节直接进入客户文件节点，平台保存管理信息和发布结果。

回到“客户节点”，选择“仅文件服务”路径。在“文件独立接入验证”中选择同一项目和测试环境，点击“刷新已发布安装包”，选择已确认的当前发布版本。

## 完成完整下载验证

1. 选择需要验证的公网或内网及 VPN，点击“保存文件验证范围”。保存范围后尚未完成接入。
2. 在“从目标网络完整读取”选择确实位于该网络的客户验证节点，可使用文件节点本机。
3. 点击“开始文件完整下载验证”。验证节点完整读取指定发布对象，核对长度和 SHA256；平台只接收验证结果。
4. 所选网络均成功且当前发布仍一致时，页面显示“文件接入验证完成”。在实际下载设备上继续检查下载页面和应用安装效果。

发布版本发生变化后，应重新选择当前版本验证。旧记录仍可查看，但不代表新的发布或当前服务可用。失败或响应丢失时按[原请求恢复]({{ '/versions/mashuyun-20261110-r1/maintenance/' | relative_url }})继续。

## 以后增加构建机

保留原文件节点，在引导选择“分机部署”，确认文件机就绪并刷新、下载更新后的配置，再按[分机部署]({{ '/versions/mashuyun-20261110-r1/split/' | relative_url }})接入构建机。构建机独立检查 SDK 和授权，沿用组织原到期时间。
