# 分机部署

分机部署将文件机与构建机放在不同机器，先完成文件机就绪，再把构建机关联到它。文件机可以使用 Apple 芯片 Mac、Linux amd64 或 Linux arm64；构建机使用 Apple 芯片 Mac 或 Linux amd64。

## 先接入文件机

1. 在平台“客户节点 → 开始接入”选择“分机部署”。首个阶段的本机职责是“仅文件服务”。
2. 准备文件机的 Docker、存储、域名和 HTTPS，下载配置与文件机平台对应的批准节点包，完成[核验]({{ '/versions/mashuyun-20261110-r2/downloads/' | relative_url }})。
3. 在文件机运行接入助手，选择“仅文件服务”。生成文件节点登记码，沿原身份完成登记、自动授权、安装和服务检查。
4. 回到平台确认文件节点的许可、存储和下载入口已就绪。失败时处理文件机问题，保留原节点继续，不要提前接入构建机。

## 刷新配置后接入构建机

文件机就绪后，在平台引导中点击“刷新接入配置”，再“下载更新后的配置”。此时引导应显示“仅构建”，配置中包含已绑定的文件节点地址。此前下载的旧配置不能代替这一步。

将更新后的配置带到构建机，选择构建机对应平台的批准包并完成核验。打开接入助手，选择“仅构建”，配置实际 SDK、源码访问与应用签名材料，使用单独的构建机登记码接入。

构建机需要从自身网络访问文件机，且信任文件机证书。构建机要独立通过本机授权、SDK 和机器指纹核验；文件机成功不会自动启用构建机。后接构建机使用组织原有试用期限，不重新起算。

## 验证完整路径

在真实项目与测试环境执行构建，确认产物到达已绑定文件机并发布。完成构建机到文件目标的证书与连接检查，再执行接入验证要求的完整 HTTPS 下载，核对长度和摘要。

如果目标网络同时包含公网与内网或 VPN，应分别选择真实位于这些网络的客户验证节点并完成下载。只在文件机本地验证，不能证明其他网络能够访问。

遇到中断或地址、证书问题，参见[维护与恢复]({{ '/versions/mashuyun-20261110-r2/maintenance/' | relative_url }})。若暂时不需要构建机，可先按[仅文件服务]({{ '/versions/mashuyun-20261110-r2/fileservice/' | relative_url }})完成上传、发布和下载验证。
