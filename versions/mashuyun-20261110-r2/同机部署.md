# 同机部署

同机部署在一台机器上运行构建与文件服务，适用于 Apple 芯片 Mac 和 Linux amd64。Mac 可以同时执行 iOS 构建并提供文件下载；文件服务和数据库在 Docker 中运行，构建使用 macOS 本机工具链。

## 安装一台合并节点

1. 按[环境准备]({{ '/versions/mashuyun-20261110-r2/requirements/' | relative_url }})准备构建 SDK、源码访问、应用签名材料、Docker、存储和下载域名证书。
2. 在平台“客户节点 → 开始接入”选择“同机部署”和实际机器平台，下载本组织配置与批准版本。
3. 完成[独立验包]({{ '/versions/mashuyun-20261110-r2/downloads/' | relative_url }})，打开接入助手，选择 `mam-connect.json`。
4. 本机职责选择“合并部署”，选择全新安装目录，填写文件服务入口并选择实际构建技术栈与 SDK。检查缺项，处理后沿原草稿重新检测。
5. 在平台生成同时包含“构建机”和“文件节点”的登记码，回到原向导登记并继续。完成浏览器要求的首次确认后，等待自动授权、安装、启动和服务检查。

已有文件节点绑定时，不要重新生成第二个文件节点。同一组织已有文件机且需要新增构建机，应使用[分机部署]({{ '/versions/mashuyun-20261110-r2/split/' | relative_url }})；原节点安装中断按[维护与恢复]({{ '/versions/mashuyun-20261110-r2/maintenance/' | relative_url }})继续。

## 验证构建与发布

回到平台原组织，确认节点在线、机器授权有效、文件存储与 HTTPS 就绪。构建能力仍需由实际 SDK、机器指纹和就绪核验确认，不能只看到 Agent 在线就开始判断接入完成。

创建或选择真实项目与测试环境，配置源码、签名引用和构建节点权限，执行测试构建。确认任务成功、产物归档、当前版本发布，再在接入验证中选择真实任务与发布版本，完成目标网络的完整 HTTPS 下载和摘要检查。

在实际使用的浏览器或手机上打开下载入口，并验证应用安装效果。应用签名和设备安装条件由应用本身决定，文件下载成功不代表应用能够在所有设备安装。

## 保持文件服务可用

构建和文件下载共享同一台机器的磁盘与运行时间。机器休眠、Docker 退出或磁盘耗尽会影响下载；长期构建时关注文件服务磁盘余量。备份、证书换发和停机操作按[维护与恢复]({{ '/versions/mashuyun-20261110-r2/maintenance/' | relative_url }})执行。
