# 环境准备

先确认机器平台与职责，再准备对应依赖。实际可安装范围以当前登录平台的批准下载列表为准。

## 机器支持范围

| 平台 | 同机部署 | 仅构建 | 仅文件服务 |
| --- | --- | --- | --- |
| Apple 芯片 Mac，arm64 | 支持 | 支持，含 iOS | 支持 |
| Linux，amd64 | 支持 | 支持，不含 iOS | 支持 |
| Linux，arm64 | 不支持 | 不支持 | 支持 |

本期不支持 Intel Mac。Linux 支持 Ubuntu 24.04、26.04 和 Debian 12；使用普通安装用户。Linux 用户服务需要可用的 systemd 用户会话和 linger，按接入助手给出的说明配置，以便退出 SSH 后继续运行。

Mac 上 Agent 和构建 Worker 原生运行；文件服务、MySQL、Redis 和下载 HTTPS 入口使用 Linux arm64 容器。Docker 需要保持运行，Mac 休眠或关机会中断构建和下载。

## 文件服务所需材料

- 本机 Docker 引擎及 Docker Compose。安装用户应能访问本机引擎，不能用远程 Docker context 代替。安装后保持原引擎和数据目录。
- 客户本地持久化存储及全新安装目录。为安装包、数据库、日志和备份留出空间，避免与其他应用共用已有业务目录。
- 下载域名及完整 HTTPS 证书链、私钥。域名应解析到下载设备实际能够访问的入口；浏览器、手机与验证节点都需要信任证书。
- 从使用者网络访问下载入口的路径。公网与内网或 VPN 分别验证，文件机本地可达不能证明手机可达。

已有同机 HTTPS 网关时，可在向导选择该方式，将网关上游指向助手显示的本机回环端口。证书保留在网关，公网下载仍使用 HTTPS。选择本机证书方式时，在本机选择证书链和私钥；可选 CA 文件不会自动安装到系统或手机的信任库。

安装 Docker 请查看 [Mac 安装说明](https://docs.docker.com/desktop/setup/install/mac-install/)、[Ubuntu 安装说明](https://docs.docker.com/engine/install/ubuntu/)、[Debian 安装说明](https://docs.docker.com/engine/install/debian/)及 [Compose 安装说明](https://docs.docker.com/compose/install/)。

## 构建机额外依赖

只准备实际项目需要的技术栈。Android 使用匹配项目的 JDK、SDK Platforms、Build Tools 和签名材料；Flutter 使用项目指定 Flutter；iOS 需要 Mac、Xcode、分发身份和描述文件。鸿蒙、uni-app、Cordova 按向导选择对应工具及目标平台。

SDK 路径、版本和源码访问权限需要与你的项目一致。向导可以发现已有工具，但不会自动下载依赖、接受第三方许可或修改项目配置。源码 Token、SSH 私钥和应用签名私钥只在本机配置。

## 网络与运行条件

安装机器需要出站连接麻树云、GitHub、GHCR 和所选依赖来源。构建机还需能访问源码仓库及客户文件机。下载设备需要访问客户下载域名；客户业务文件由文件节点直接提供。

安装后继续保持机器、Docker、持久化存储和下载网络可用。常驻使用时，应安排 Mac 的持续运行与用户会话；重启后检查原节点服务及下载入口，不能仅凭上次成功状态判断当前可用。
